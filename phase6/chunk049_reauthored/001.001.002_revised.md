# Create Customer resource in staff Filament panel

## Goal
Build the `CustomerResource` for the staff Filament panel with list, create, edit, and delete pages.

## Acceptance criteria
- [ ] `app/Filament/Resources/CustomerResource.php` exists and is registered in the staff panel.
- [ ] List page shows customers with search, sort, and pagination.
- [ ] Create and edit forms include `client_id`, `name`, `division_id`, and `email`.
- [ ] Soft delete or archive is supported.
- [ ] Feature tests pass.

## Permitted paths
- `illima-dashboard/app/Filament/Resources/CustomerResource.php`
- `illima-dashboard/app/Filament/Resources/CustomerResource/Pages/`
- `illima-dashboard/app/Models/Customer.php`
- `illima-dashboard/database/seeders/`
- `illima-dashboard/tests/Feature/CustomerResourceTest.php`

## Prohibited changes
- Do not modify customer panel files.
- Do not change the FMA API service.
- Do not add real FMA credentials to test data.

## Verification
```bash
cd illima-dashboard && php artisan test tests/Feature/CustomerResourceTest.php
```

## Manual verification (required — this chunk touches a Filament UI)
Feature tests confirm the resource's HTTP/Livewire wiring, not what it
looks like or feels like to use. Before moving this chunk to `passed`,
a human must, in a real browser against `/admin`:
- [ ] Open the Customers list page: search for a seeded customer by name
      and by `client_id`, confirm both find the right row; sort by each
      column once.
- [ ] Create a new customer through the form; confirm it appears in the
      list without a page reload glitch or console error.
- [ ] Edit an existing customer; confirm the change is reflected in the
      list immediately.
- [ ] Trigger the delete/archive action; confirm the row disappears (or
      is marked archived, per whichever behavior was actually built) and
      no error is shown.

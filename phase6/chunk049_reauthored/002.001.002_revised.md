# Build customer delivery history page

## Goal
Create a customer-facing page in the customer panel that shows the logged-in customer's delivery history with date and tank filters.

## Acceptance criteria
- [ ] Customer panel has a deliveries page.
- [ ] Table lists only the customer's deliveries.
- [ ] Filters for date range and tank number are present.
- [ ] Feature tests pass.

## Permitted paths
- `illima-dashboard/app/Providers/Filament/CustomerPanelProvider.php`
- `illima-dashboard/app/Filament/Customer/Resources/` (if used)
- `illima-dashboard/app/Filament/Customer/Pages/`
- `illima-dashboard/app/Models/Delivery.php`
- `illima-dashboard/app/Models/Customer.php`
- `illima-dashboard/app/Models/User.php`
- `illima-dashboard/tests/Feature/CustomerDeliveryHistoryTest.php`

## Prohibited changes
- Do not modify staff panel files.
- Do not create admin-only features on the customer page.

## Verification
```bash
cd illima-dashboard && php artisan test tests/Feature/CustomerDeliveryHistoryTest.php
```

## Manual verification (required — this chunk touches a Filament UI)
- [ ] Log in as the seeded customer test account (`customer@illima.test`)
      and open the deliveries page: confirm you see only that customer's
      deliveries, none from other customers.
- [ ] Apply a date-range filter that should exclude some rows; confirm the
      table updates and the excluded rows are actually gone (not just a
      client-side visual truncation).
- [ ] Apply a tank-number filter the same way.
- [ ] Clear both filters; confirm the full list returns.

## Notes
Second re-authored example for CHUNK-049. This chunk is a stronger
illustration of the "customer sees only their own data" acceptance
criterion being a security-relevant behavior, not just a display one —
worth a human confirming it directly rather than trusting a feature test's
factory/seeder setup accidentally hid a scoping bug (e.g. a missing
`where` clause that only fails with more than one customer's data
present, which a minimal test fixture might not exercise).
